# Android packaging and release

- No Android SDK on the dev PC: all Android builds run in Docker via `scripts/android/build.ps1` (image from `docker/android-build/`, outputs in `build\android-out\`). The script has named-only params (`-Rebuild`, `-Keystore`, `-KeyAlias`); every other argument is a Gradle task.
- `applicationId` `com.gig81.kiwisdrgrabber` is final. `versionName` = `appVersion`, `versionCode` derived from it (`1.2.0` → `10200`) in `androidApp/build.gradle.kts`; an APK only updates an installed one with the same signature and a higher `versionCode`.
- Signing reads `kiwi.signing.*` Gradle properties or `KIWI_SIGNING_*` env vars; without them the release is unsigned (`androidApp-release-unsigned.apk`). Locally: `.\scripts\android\build.ps1 -Keystore "$env:USERPROFILE\KiwiGrabberKeys\kiwigrabber-release.jks" :androidApp:assembleRelease` — mounts only the keystore folder read-only, asks the password (or reads `$env:KIWI_SIGNING_STORE_PASSWORD`), refuses a keystore inside the repo, then runs `apksigner verify --print-certs` on the release APKs. Never ask the user for keystore passwords and never put keys in the repo or scratchpad.
- Keys (owned by the user, outside the repo, backed up offline): app signing key `kiwigrabber-release.jks` alias `kiwigrabber` (signs the GitHub APK; would be uploaded to Play App Signing via PEPK; irreplaceable — `ANDROID_ID`, hence `GRAB-A-…` device IDs and licenses, depend on it), upload key `kiwigrabber-upload.jks` alias `upload` (only for a future Play AAB). App certificate SHA-256: `ef6d6ca3ce92c7a0471543a1fe48684247c6b7d4b7dd8c7eb368b446ec202129` (also in `release.yml` `APP_CERT_SHA256`, USER_GUIDE §12, DISTRIBUZIONE_E_RILASCI).
- A debug-signed and a release-signed APK cannot update each other and produce different device IDs: switching requires uninstalling and a new license.
- Published APKs come only from `.github/workflows/release.yml`: the `android` job (ubuntu, environment `android-release` with secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`) installs platform/build-tools from the Dockerfile ARGs, runs host tests + lint, builds the signed APK, deletes the keystore, checks certificate, `applicationId` and `versionName`, and hands `KiwiSDRGrabber-<version>.apk` to the Windows job, which adds it via `Prepare-ReleaseAssets.ps1 -ExtraFiles` to `SHA256SUMS.txt`, attestations and the draft release. `ci.yml` has an Android job (host tests, lint, debug APK, no secrets). Desktop-only jobs pass `-Pkiwi.android=false` because runners have an Android SDK preinstalled.
- Distribution is GitHub-only for now; Play Store, the Android developer verification requirement and other open points are tracked in `docs/piani/ANDROID.md`. Release checklist (including the on-device upgrade test of the draft APK): `docs/DISTRIBUZIONE_E_RILASCI.md`; Windows side: the `windows-release` skill. User docs: `docs/USER_GUIDE.md` §12.
